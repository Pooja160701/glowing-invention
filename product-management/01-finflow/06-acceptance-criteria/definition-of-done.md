# FinFlow — Definition of Done

A FinFlow story is considered Done only when all applicable conditions are satisfied.

## Product
- Requirement is implemented according to the approved story.
- Acceptance criteria pass.
- Scope changes are documented.

## UX
- Primary workflow is usable.
- Empty, loading, success, and error states are handled.
- Accessibility requirements are considered.

## Engineering
- Code is reviewed.
- Automated tests cover critical logic.
- Error handling is implemented.
- Security/privacy requirements are addressed.

## Data
- Financial calculations are validated.
- Relevant analytics events are implemented.
- Event properties follow the tracking specification.

## QA
- Happy path tested.
- Important edge cases tested.
- Regression checks completed.

## Documentation
- Relevant API/product documentation updated.
- Known limitations documented.

## Release
- Feature is deployable.
- Monitoring/observability exists where required.
- Product owner accepts the result.
