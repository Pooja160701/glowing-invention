# MediConnect Trello Sprint Board

## Sprint objective
Deliver a reliable patient booking journey while establishing operational and security foundations for controlled MVP validation.

## Ready for Development
- [PAT] Provider discovery
- [PAT] Availability search
- [OPS] Staff scheduling
- [ANA] Booking funnel events

## In Progress
- [PAT] Atomic booking
- [SEC] RBAC and organization isolation
- [UX] Booking flow usability validation

## QA / Validation
- [PAT] Booking confirmation
- [SEC] Audit logging

## Ready for Release
Cards enter this list only after acceptance criteria, QA evidence, security/privacy checks where applicable, analytics verification, and release-note readiness.

## Blocked / Needs Decision
Example blockers:
- Availability source has stale data.
- Provider schedule rules are not defined.
- Notification provider contract is unresolved.
- Organization authorization boundary requires an architecture decision.

## Sprint review questions
1. Did the booking journey become more reliable?
2. Which cards were blocked and why?
3. What escaped QA?
4. What evidence changed product assumptions?
5. Which metric should be monitored after release?
