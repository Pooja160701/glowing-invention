# Trello Board Structure

## Board goal
Give the team a simple visual view of work moving from product backlog through validation and release.

## Workflow
Product Backlog → Ready for Development → In Progress → Code Review → QA / Validation → Ready for Release → Released

Use Blocked / Needs Decision for work that cannot safely progress.

## Working agreements
- Every card has one clear outcome.
- Every card links to a requirement or product decision.
- P0 work is explicitly labeled.
- Blocked cards explain the blocker.
- Cards do not move to Ready for Release without acceptance criteria and QA evidence.
- Released cards link to release notes and relevant metrics.

## Grouping
Use labels and card prefixes to provide lightweight workstream grouping.

Prefixes:
- [PAT] Patient
- [OPS] Operations
- [SEC] Security
- [ANA] Analytics
- [UX] Experience
- [PLAT] Platform
